PARTE 1 — API_URL PARA RENDER + NETLIFY
━━━━━━━━━━━━━━━━━━━━━━

1. Localize o arquivo JS que faz as requisições (provavelmente em `frontend/` ou no HTML principal).
   - Procure por `fetch("/api/` ou `API_URL`.

2. Crie uma constante global:
   ```js
   const API_URL = "https://l4doc-api.onrender.com";
e troque todas as chamadas de:

js
fetch("/api/alguma-coisa" ...)
para:

js
fetch(`${API_URL}/api/alguma-coisa` ...)
inclusive:

geração de todos documentos (ex.: /api/generate-all ou similar)

qualquer endpoint de histórico, se houver consumo no front

Certifique-se de que nos ambientes locais isso continua funcionando:

Se você detectar que o código roda tanto local quanto em produção, pode usar:

js
const API_URL = window.location.hostname.includes("localhost")
  ? "http://127.0.0.1:5000"
  : "https://l4doc-api.onrender.com";
Se isso for simples de aplicar, use essa abordagem; se não, use apenas a URL do Render.

Crie um arquivo netlify.toml na raiz com:

text
[build]
  publish = "frontend"
  command = "npm run build || echo 'no build step'"

[[redirects]]
  from = "/api/*"
  to = "https://l4doc-api.onrender.com/api/:splat"
  status = 200
  force = true
OBS: se o front for estático puro (só HTML/JS), o comando de build pode ser ignorado; o importante é o publish = "frontend".

Verifique se as rotas estáticas (/, /curadoria, /guia) continuam acessíveis no Netlify
e que as chamadas de geração usam o domínio do Render.
